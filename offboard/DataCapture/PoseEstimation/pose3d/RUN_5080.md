# pose3d on RTX 5080 (Blackwell / torch 2.7) — Run Recipe

Verified working 2026-07-22 on the 5080 box (`siyu@100.79.88.6`, Ubuntu, miniforge3).
This documents **how to reproduce** the full 3D whole-body pose pipeline (SMPLer-X-H32 +
multi-view DLT) end-to-end, including every compat fix needed for torch 2.7 / Blackwell.

## TL;DR
```bash
source ~/miniforge3/etc/profile.d/conda.sh && conda activate pose3d
cd ~/robomemo-core/offboard/DataCapture/PoseEstimation/pose3d/third_party/SMPLer-X/main  # CWD MUST be main/
python ~/robomemo-core/offboard/DataCapture/PoseEstimation/pose3d/run_pipeline.py --recording 0721-1 --no-align
# -> dataset/Ego4WholeBody/0721-1/pose3d_out/poses.json  (+ viz/)
```

## 2. Run command

```bash
cd ~/robomemo-core/offboard/DataCapture/PoseEstimation/pose3d/third_party/SMPLer-X/main
#   ⚠️ CWD MUST be SMPLer-X main/. Its config paths
#   (transformer_utils/configs/..., nested _base_/...) resolve RELATIVE TO CWD.
#   run_pipeline.py resolves its OWN paths via __file__ (pose3d pkg, config.yaml,
#   dataset, output), so it runs correctly from this CWD.
python ~/robomemo-core/offboard/DataCapture/PoseEstimation/pose3d/run_pipeline.py \
    --recording 0721-1 [--no-align] [--max-frames N]
```

Options:
- `--recording <name>` — recording dir under `Ego4WholeBody/`.
- `--no-align` — reuse existing `*_aligned.MP4` (skips the ~8 min audio-align re-encode). The **first** run on a recording must align (omit the flag).
- `--max-frames N` — cap frames (smoke test).
- `--device cuda` (default).

Detached run (tmux is **not** installed on this box; use `setsid` + log):
```bash
setsid bash -c "python .../run_pipeline.py --recording 0721-1 --no-align > /tmp/fullrun.log 2>&1; echo EXIT=\$? >> /tmp/fullrun.log" </dev/null >/dev/null 2>&1 &
```

## 3. Patches applied (reproducible recipe)

All are **mechanical torch-2.7 / Blackwell compat fixes** (no model-logic change). Backups saved as `*.bak`.

### 3.1 mmcv-full 1.7.1 source build (the Blackwell crux)
No cu126/torch2.7 wheel exists. Source-build, **but** mmcv 1.7.1 compiles with `-std=c++14`
while torch 2.7 headers require C++17 → compile fails (`std::optional/string_view/variant`).
Patch the sdist `c++14`→`c++17` first:
```bash
pip download --no-deps --no-binary :all: mmcv-full==1.7.1 -d /tmp/mmcv_src
cd /tmp/mmcv_src && tar xzf mmcv-full-1.7.1*.tar.gz && cd mmcv-full-1.7.1
grep -rlF "c++14" . | xargs sed -i 's/c++14/c++17/g'      # the only wall (mmcv 1.7.1 is post-THC)
MMCV_WITH_OPS=1 FORCE_CUDA=1 TORCH_CUDA_ARCH_LIST="12.0" \
  pip install -v --no-build-isolation /tmp/mmcv_src/mmcv-full-1.7.1
# verify:
python -c "from mmcv.ops.roi_align import roi_align; import mmcv; print(mmcv.__version__)"  # 1.7.1
```

### 3.2 Dependency version pins (torch-2.7 incompats)
```bash
pip install "setuptools==75.8.0" "yapf==0.32.0" "scikit-image==0.24.0" "numpy==1.26.4" "scipy==1.12.0" "plyfile==0.8.1" cython
```
- `setuptools 75.8.0` — mmcv 1.7.1 `setup.py` does `from pkg_resources import ...` (removed in setuptools 83).
- `yapf 0.32.0` — mmcv `config.py` calls `FormatCode(..., verify=True)`; yapf ≥0.40 dropped `verify`.
- `scikit-image 0.24.0` + `numpy 1.26.4` — scikit-image 0.26 requires numpy≥2 (breaks mmcv/cv2).
- `plyfile 0.8.1` — plyfile 1.1.4 requires numpy≥2.

### 3.3 SMPLer-X upstream patches (3 files)
1. **`third_party/SMPLer-X/common/utils/human_models.py`** — wrap the module-level
   `smpl = SMPL()` in `try/except → smpl=None`. SMPLer-X H32 inference uses only
   `smpl_x` (SMPL-X); the SMPL body model is **vestigial** (only
   `preprocessing.process_human_model_output`'s `'smpl'` dataset branch uses it —
   never the inference path). Avoids needing license-gated `SMPL_NEUTRAL/MALE/FEMALE.pkl`.
2. **`third_party/SMPLer-X/common/base.py`** — guard the testset import:
   `if cfg.testset != 'na': exec('from '+cfg.testset+' import '+cfg.testset)`.
   The wrapper sets `testset='na'` for inference; base.py unconditionally imported it
   → `ModuleNotFoundError: na`. The testset module is vestigial for inference.
3. **`torchgeometry/core/conversions.py`** (pip pkg, lines 302–304) — `1 - bool_mask`
   → `~bool_mask` (3 lines). torch 2.7 forbids bool subtraction; torchgeometry 0.1.2
   (torch-1.x era) used the old idiom. Logic unchanged (masks combined via `*`, then
   `.type_as()`→float).

### 3.4 Invocation + symlinks
4. **CWD = `third_party/SMPLer-X/main/`** (see §2). SMPLer-X relative config paths resolve
   from CWD. *(Cleaner permanent fix: wrapper does `os.chdir(repo/main)` — adapter change.)*
5. **`dataset/models/smplx/smplx` → `dataset/models/smplx`** symlink — `smplx.create(path,
   model_type)` appends `model_type/`; the wrapper passes the smplx dir, so this symlink
   lets it find the `.npz`. *(Cleaner fix: wrapper passes `os.path.dirname(smplx_model_dir)`.)*
6. **`DataCapture/Data_Preprocessing/align_audio.py`** — must be present (the time-align
   step shells out to it). rsync initially missed it; scp the repo copy.

### 3.5 SMPL-X model files in `dataset/models/smplx/`
Present (user-provided): `SMPLX_NEUTRAL/MALE/FEMALE.npz` (body model) +
`SMPLX_to_J14.pkl` + `MANO_SMPLX_vertex_ids.pkl` + `SMPL-X__FLAME_vertex_ids.npy`.
**No `SMPL_*.pkl` needed** (patched out, §3.3.1). All MPI license-gated.

## 4. Output  (`dataset/Ego4WholeBody/0721-1/pose3d_out/`)
- **`poses.json`** — per-frame 78-joint 3D poses (the main deliverable).
- `calibration.json` — multi-view calibration (reused on subsequent runs).
- `viz/` — `H/L/R_XXXXXX.png` (2D pose overlay on the real frame) + `body3d_XXXXXX.png`
  (3D skeleton). `viz_num_frames` in `config.yaml` controls sample density (default 12).

## 5. `poses.json` structure
- Header: `version 1.0`, `fps 59.94`, `n_joints 78` (24 body + 27/hand ×2),
  `scale metric_meters`, `board_square_size_m 0.02`, `timeline_master H`.
- `frames[i]`: `t` (sec), `frame_idx`, `primary_view`, `joints[name] = {xyz:[x,y,z], conf, source}`.
- `xyz` in **meters**, **H-camera frame**.
- `source`: `triangulated` (body, DLT across views, metric) · `video` (single-view hand) ·
  `derived` (interpolated/extrapolated) · `singleview` (body fallback) · `missing`.

## 6. ⚠️ Calibration quality caveat
The **0721-cali** stereo calibration is **poor** (stereo RMS: H-L ~75 px, H-R ~13 billion px;
should be <1 px — board corner-orientation / coverage problem).
Consequences:
- `triangulated` coverage is low (~31%); many body joints fall back to single-view (the
  `reproj_error_thr_px` filter drops bad-view pairs).
- **Metric values are approximate** (extrinsics/scale off).
- The pipeline RUNS correctly — this is a calibration **data** issue, not a code bug.
- **Fix for accurate metrics**: re-record `0721-cali` with the checkerboard (11×8 inner,
  20 mm squares) clearly visible to **all 3 cameras simultaneously** across many frames;
  or tune `calibration.board_cols/rows/pattern_fallback` in `config.yaml`.
